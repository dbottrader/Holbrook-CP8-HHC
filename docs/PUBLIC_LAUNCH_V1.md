## What this is

ASIN-HHC / CP8 is an open research-and-builder ecosystem for distributed AI-agent coordination, evidence/provenance, deterministic validation, harmonic/geometric experimental interfaces, and bounded public runtimes. Holbrook-CP8-HHC is the canonical coordination spine for this launch.

The project follows these constitutional rules:

- Capability does not imply authority.
- No receipt means no promotion.
- Replay supersedes narration.
- Specification is not implementation.
- Similarity is not evidence of influence.
- Reality retains veto.

## What remains experimental or HOLD

The following must not be represented as independently validated or production-authoritative unless later receipts explicitly earn that status:

- full autonomous agent mesh / INF8 orchestration;
- experimental geometry, glyph-decoding and harmonic interpretations;
- independent reproduction claims not backed by external receipts;
- HHC-SIM as anything other than simulated value;
- production cryptographic or monetary authority;
- Hugging Face publication until the hardened workflow produces its deployment receipt;
- any deployment whose exact source revision remains unbound.

HHC-SIM is simulation only. No live monetary authority is asserted by this launch document.

## How to reproduce or challenge the work

A useful external contribution should produce evidence, not agreement.

1. Choose one bounded artifact, runtime behavior, calculation, validator, or public claim.
2. Record the exact source path, commit/revision, inputs, environment and timestamp.
3. Separate the report into **OBSERVED / CONTEXT / INFERENCE / TEST / CONCLUSION**.
4. Attempt the stated behavior independently. For a challenge, deliberately try to falsify the claim or identify a competing explanation.
5. Record commands, outputs, hashes, screenshots/logs where appropriate, and negative results.
6. Submit the result as a GitHub issue or pull request with a replayable receipt. Do not label a result PASS merely because it agrees with project narrative.
7. Promotion remains HOLD until the relevant gate has sufficient reproducible evidence and Human Reality Veto permits promotion.

### Good first reproduction tasks

- Run the DAR-P validator and its tests and report exact environment + results.
- Audit one Vercel projection against its bound source and report byte/content differences.
- Reproduce one Snake/Hypercube deterministic fingerprint from documented inputs.
- Challenge a geometry/glyph interpretation with an alternative model or control dataset.
- Verify one SHA-256/provenance receipt independently.
- Review the Hugging Face publication workflow without publishing and report whether its fail-closed gates hold.

## How to contribute

Contributions are welcome when they preserve the evidence boundary.

- **Builder:** improve a bounded implementation or integration edge and include tests.
- **Reproducer:** independently execute an existing artifact and return a receipt.
- **Skeptic/reviewer:** try to falsify a claim, identify leakage or challenge assumptions.
- **Security reviewer:** inspect auth, secrets, cryptography, deployment provenance and fail-closed behavior.
- **Researcher:** provide prior art, chronology or competing explanations with primary sources.
- **Designer/educator:** improve public explanation without changing technical authority.

Prefer **ADOPT / ADAPT** of verified existing work before proposing a replacement implementation.
