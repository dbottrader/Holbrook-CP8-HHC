## Purpose

This page makes the public record easy to inspect without requiring trust in a retrospective narrative. It identifies what the Git history establishes, what the repository hashes establish, what remains a project-source claim, and what would require independent reproduction.

This record documents chronology and technical lineage. It does **not** accuse any person or project of copying, infringement, or derivation merely because similar language or architecture appears elsewhere.

## Core CP8 governance propositions

The repository publicly records the following governing propositions:

- Capability does not imply authority.
- No receipt means no promotion.
- Replay supersedes narration.
- Specification is not implementation.
- No mechanism may silently convert uncertainty into authority.
- Reality retains veto.

Their practical consequence is that a probabilistic model may assist with proposals and interpretation, while authoritative claims and state transitions require evidence, verification, bounded permissions, and replayable receipts.

## Evidence classes

Use these labels when describing CP8 artifacts:

| Label | Meaning |
|---|---|
| `GIT_VERIFIED` | A public commit establishes that specified bytes or text existed in the repository by the commit timestamp. |
| `HASH_VERIFIED` | A digest can be recomputed from the referenced artifact and matches the recorded value. |
| `LOCALLY_EXECUTED` | The project reports a local execution and preserves a receipt or output; this is not independent reproduction. |
| `SOURCE_ARCHIVE` | The repository preserves earlier project material whose internal dates or narrative require separate corroboration. |
| `SELF_REPORTED_ANCHOR` | A claim supplied by the project steward but not independently verified by this repository record. |
| `INDEPENDENTLY_REPRODUCED` | An unaffiliated party has reproduced the result and published sufficient methods and receipts. |

Repository inclusion alone must never be described as independent verification.
