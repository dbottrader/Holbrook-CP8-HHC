## What this is

ASIN-HHC / CP8 is an evolving research-and-builder ecosystem spanning evidence-governed AI workflows, provenance/receipts, deterministic geometry and visualization experiments, agent coordination, and public runtime demonstrations.

The project uses a strict evidence discipline:

**OBSERVED → CONTEXT → INFERENCE → TEST → CONCLUSION**

and a fixed investigation spine:

**ARTIFACT → MEASUREMENT → REPRESENTATION → DECODING → REPLICATION → INTERPRETATION → ORIGIN HYPOTHESIS → CHALLENGE → REVISION**

Core invariants:

- Capability ≠ Authority.
- No Receipt = No Promotion.
- Specification ≠ Implementation.
- Similarity ≠ demonstrated influence.
- Negative evidence is evidence.
- Independent branches remain isolated until closure/synthesis.
- Reality retains veto; promotion authority remains human.
- ADOPT / ADAPT existing work before BUILD.

## Reproduce something

A useful reproduction must produce evidence, not merely a matching opinion.

1. Choose one bounded artifact or runtime claim.
2. Record the exact source commit/file and, where available, its SHA-256.
3. State the claim using OBSERVED / CONTEXT / INFERENCE / TEST / CONCLUSION.
4. Execute the relevant code, geometry, workflow, or integrity test independently.
5. Record environment, inputs, outputs, failures, timestamps, and hashes.
6. Attempt at least one discriminating or adversarial test that could falsify the claim.
7. Return a receipt or reproducible report.
8. Keep the result HOLD when evidence is incomplete.

A failed reproduction is valuable evidence and should be preserved rather than hidden.

## Challenge a claim

When challenging a project claim:

- identify the exact claim and source;
- distinguish observation from interpretation;
- provide an alternative explanation where possible;
- specify evidence that would discriminate between alternatives;
- preserve contradictions in the record;
- do not treat consensus, persuasion, or agent count as proof.

## Contribute

High-value first contributions include:

- independently reproduce one existing CP8 test/run and submit the receipt;
- audit one public runtime against its claimed source revision;
- locate and bind an unbound historical artifact to its source/hash;
- adversarially review a HOLD claim and propose a falsification test;
- improve contributor/reproduction tooling without weakening evidence gates;
- review security, determinism, provenance, or deployment boundaries;
- submit a narrowly scoped implementation that replaces a documented missing edge rather than rebuilding an existing subsystem.

For code changes, use a focused branch/PR and identify the artifact, evidence level, tests, and authority boundary affected.
