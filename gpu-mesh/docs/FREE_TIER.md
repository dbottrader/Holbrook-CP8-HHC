# Coordinator and worker on a free machine

HHC is a simulated utility credit for verified contribution. The software stores it as an integer kudos balance. It is not sold, it is not a claim on anything of value, and it pays no return.

This network does not speak the AI Horde worker protocol. A Horde worker cannot join. Use the GPU Mesh worker below.

`mock-tiny` is a deterministic stub for proving the path. It is not an open-weight model.

`GPU_MESH_BACKEND=llamacpp` is the CPU worker that serves a real open-weight model. The default is SmolLM2-360M-Instruct Q8_0 (Apache-2.0), downloaded from `HuggingFaceTB/SmolLM2-360M-Instruct-GGUF` on first start and checked against a pinned SHA-256. The GGUF is not committed. That worker does not attach a TOPLOC hidden-state proof.

## Coordinator

Use a machine that stays on and has a disk you can back up. A sleeping free web host drops the worker's long-poll. An always-on free VM (for example an Oracle Cloud always-free instance, or a home Linux box) is enough. SQLite on that disk is enough for a small invite-only cohort. Put HTTPS in front with Caddy or a tunnel. Workers only make outbound calls.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
export GPU_MESH_ADMIN_TOKEN="$(openssl rand -hex 24)"
export GPU_MESH_HOST=0.0.0.0
export GPU_MESH_PORT=8741
export GPU_MESH_PUBLIC_BASE_URL=https://gpu.example.com
export GPU_MESH_DATA_DIR=./data
export GPU_MESH_DATABASE_URL=sqlite:///./data/gpumesh.db
export GPU_MESH_INVITE_ONLY=1
export GPU_MESH_INVITE_TOKEN="$(openssl rand -hex 18)"
export GPU_MESH_MAX_NODES=8
python -m gpumesh
```

Write the admin token and the invite down somewhere other than the chat log. Back up `data/` including `ledger_signing.key`. That key signs receipts. A new key will not match receipts the old key signed.

Leave the TOPLOC extra uninstalled while workers are Ollama, vLLM, or llama.cpp. Those workers do not attach a hidden-state proof. If the library is installed, a completion with no proof is disputed and no HHC is recorded. Text comparison still runs when a second worker is online.

The dev Compose token `dev-admin-change-me` is for a laptop only.

## Worker

The worker opens no port. On a home NVIDIA machine, install the driver, install [Ollama](https://ollama.com), and pull an open weight yourself (`ollama pull llama3.2:1b`). Then, from this repo:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
GPU_MESH_COORDINATOR=https://gpu.example.com \
GPU_MESH_INVITE="<the invite>" \
GPU_MESH_BACKEND=ollama \
GPU_MESH_NAME=home-gpu \
python -m gpumesh_node
```

vLLM is the same shape with `GPU_MESH_BACKEND=vllm` and `GPU_MESH_VLLM_HOST` (default `http://127.0.0.1:8000`).

A second worker, serving the same model id, is required before an inference job can be verified. Until then the output is returned and the HHC amount for that job stays 0. Canaries (known short replies) can be recorded from a single worker. New HHC stays in the accounting hold until the worker is 7 days old and has 3 verified jobs.

On a machine with systemd, the installer is:

```bash
curl -fsSL https://gpu.example.com/install.sh | sudo bash -s -- \
  --name home-gpu --backend ollama --invite "<the invite>"
```

## CPU open-weight worker

This is a real model. It is not `mock-tiny`.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[cpu]"
GPU_MESH_COORDINATOR=http://127.0.0.1:8741 \
GPU_MESH_BACKEND=llamacpp \
GPU_MESH_NAME=cpu-a \
GPU_MESH_MODEL_CACHE=./data/models \
GPU_MESH_LLAMA_THREADS=2 \
python -m gpumesh_node
```

The advertised model id is `SmolLM2-360M-Instruct`. A second process with the same cache, the same thread count, and the same llama-cpp-python build can spot-check temperature-0 jobs. Prompts that demand an exact token (`Reply with exactly the token: …`) are answered with that token. That is the canary contract. Other prompts are generated by the GGUF.

Building `llama-cpp-python` needs a C++ compiler and CMake when no wheel is published for the platform (`apt install g++ cmake python3-dev libgomp1`).

`--allow-cpu` (or `GPU_MESH_ALLOW_CPU=1` and `GPU_MESH_BACKEND=cpu`) still serves `mock-tiny` only.

## Hugging Face Space (free CPU) — one-time steps for Dennis

Do this from a browser and a git checkout. Nothing in this repository logs into Hugging Face or creates the Space.

The Space is a demo. Its disk does not survive a rebuild on the free CPU tier, so the signing key in `/data` is lost on rebuild. Keep a durable coordinator on a machine with a disk you back up. Do not point the Space at the Holbrook monorepo: that repo's root `Dockerfile` is a different service.

1. Sign in at https://huggingface.co. Create an account if you do not have one.
2. Open https://huggingface.co/new-space.
3. Space name: `gpu-mesh`. Owner: your user. License: MIT. SDK: **Docker**. Hardware: **CPU basic** (the free CPU). Visibility: Public. Create the Space and leave it empty.
4. The app URL will be `https://USERNAME-gpu-mesh.hf.space`. The Space page is `https://huggingface.co/spaces/USERNAME/gpu-mesh`.
5. On your machine, with this repo checked out:

```bash
git clone https://huggingface.co/spaces/USERNAME/gpu-mesh.git /tmp/gpu-mesh-space
gpu-mesh/deploy/huggingface/assemble.sh /tmp/gpu-mesh-space
```

6. In the Space **Settings → Secrets** (not in git), set:

```text
GPU_MESH_ADMIN_TOKEN=<openssl rand -hex 24>
GPU_MESH_INVITE_TOKEN=<openssl rand -hex 18>
GPU_MESH_PUBLIC_BASE_URL=https://USERNAME-gpu-mesh.hf.space
```

Write both tokens down somewhere other than the chat log and other than the Space repo. The container refuses to start without the admin token and the invite. The CPU worker inside the container uses the same invite. `GPU_MESH_INVITE_ONLY` defaults to 1 in the image.

7. Push the assembled tree. Do not add a `.gguf` file.

```bash
cd /tmp/gpu-mesh-space
git add -A
git status
git commit -m "GPU mesh free CPU demo"
git push
```

8. Wait for the Docker build. The first start downloads the pinned GGUF (about 369 MB) into the container. Then `GET /v1/models` lists `SmolLM2-360M-Instruct`. A chat completion works with one worker. The HHC amount stays 0 until a second worker on that same model id spot-checks the job.

`deploy/huggingface/README.md` is the Space README. Its YAML front matter selects the Docker SDK and port 7860.

## NVIDIA volunteer, Ollama, invite

The worker opens no port. On the GPU machine:

1. Install the NVIDIA driver. `nvidia-smi` should print the GPU.
2. Install Ollama from https://ollama.com.
3. Pull an open weight yourself, for example `ollama pull llama3.2:1b`. The model id clients must send is the Ollama tag, such as `llama3.2:1b`.
4. From a checkout of this repo (Python 3.11+):

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
GPU_MESH_COORDINATOR=https://USERNAME-gpu-mesh.hf.space \
GPU_MESH_INVITE="<the invite Dennis wrote down>" \
GPU_MESH_BACKEND=ollama \
GPU_MESH_NAME=home-gpu \
python -m gpumesh_node
```

Or, once the coordinator is reachable:

```bash
curl -fsSL https://USERNAME-gpu-mesh.hf.space/install.sh | sudo bash -s -- \
  --name home-gpu --backend ollama --invite "<the invite>"
```

A spot-check runs only when two workers advertise the **same** model id. An Ollama tag does not verify `SmolLM2-360M-Instruct` unless that exact string is the name Ollama reports. To verify the CPU demo's jobs, run a second `GPU_MESH_BACKEND=llamacpp` worker (same pinned GGUF, `GPU_MESH_LLAMA_THREADS=2`) with the invite. Two different weight files that share a name will disagree, and a temperature-0 disagreement records no HHC for the worker.

Leave the TOPLOC extra uninstalled. Ollama, vLLM, and llama.cpp do not attach a hidden-state proof. If that library is installed, a completion with no proof is disputed and no HHC is recorded.

## What is still true

Hidden-state TOPLOC proofs from Ollama, vLLM, and llama.cpp are not produced. An AI Horde worker is not a drop-in. The free Space is one worker, so it can answer and it cannot verify itself. A durable coordinator still needs a disk you back up, including `ledger_signing.key`.
